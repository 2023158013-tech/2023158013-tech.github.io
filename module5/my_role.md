# ⚙️ 맡은 기능 (Module 5)

모듈 1에서 **단순 반복문 기반의 콘솔 쪽지 기능**으로 시작했던 메시지 도메인을 **모듈 3(1:1 메시징 및 DB 설계) ➔ 모듈 4(다대다 확장 및 STOMP 웹소켓 실시간 연동) ➔ 모듈 5(AES 양방향 자동 암호화 및 Typing Indicator 인프라)**에 걸쳐 4개 모듈 동안 단계적으로 고도화했습니다. 모듈 5에서는 이러한 실시간 메시징 인프라 위에 `AttributeConverter` 기반의 AES 메시지 양방향 암호화 메커니즘을 구축하여 DB 유출 리스크를 사전에 차단하고, 사용자 대화 경험 향상을 위해 인메모리 파이프라인 기반의 실시간 타이핑 중 표시 웹소켓 인프라를 신규 구축했습니다. 또한 Flyway 도입 과정에서 발생한 스키마 충돌과 DDL 파편화를 주도적으로 수습함과 동시에 수백 건의 배포용 더미 데이터 연관관계를 전수 검증·수선하는 DBA 리더십을 발휘했습니다.

## 💡 핵심 구현 및 예외 방어 혁신

* **메시지 자동 암호화/복호화 인프라**: `AttributeConverter`를 활용해 DB 저장 시 자동 암호화, 조회 시 자동 복호화 처리. 기존 평문 데이터와의 호환성을 고려한 예외 안전망까지 구축.
* **실시간 타이핑(Typing Indicator) 웹소켓 파이프라인**: 유저의 입력 상태를 실시간 감지하여 인원수에 따른 가공 문구(`"민수님 외 2명이 입력중입니다."`)와 ID 리스트를 방출하는 인메모리 가공 아키텍처 구축.
* **DBA 주도 마이그레이션 및 더미 데이터 수선**: 팀 내 Flyway 규칙 미숙으로 발생한 충돌 및 `USE` 구문 에러를 전면 수정하고, 수강률/가입일/완료여부 등 300여 건 이상의 더미 데이터 연관관계 정합성을 전수 수선.
* **정밀한 클라이언트 맞춤형 API 스펙 개편**: 방명록 조회 쿼리 스트링 전환, 채팅 멤버 조회 시 로그인 유저 최상단 `"(나)"` 고정 및 가나다 정렬, 친구 요청 수락/거절 시 관련 알림 자동 읽음 연동 등 UX 극대화.

## 1. 메시지 엔티티 자동 암호화/복호화 (Security & Privacy)

## 2. 메시지 입력 중(Typing) 웹소켓 인프라 및 가공 로직

사용자가 대화방에서 메시지를 작성 중일 때 상대방에게 실시간 반응성을 제공하는 웹소켓 시스템을 구축했습니다.

* **구독 및 발행 채널 분리**:
  * **발행 (Pub)**: `/pub/chat/typing/{roomId}` (`{ isTyping: true/false }`)
  * **구독 (Sub)**: `/user/sub/chat/typing/{roomId}`
* **인메모리 동적 문구 가공 파이프라인**:
  * 타이핑 중인 인원수에 따라 응답 메시지를 동적으로 생성하여 전달.
    * 0명: `""`
    * 1명: `"민수님이 입력중입니다."`
    * 2명: `"민수님, 승준님이 입력중입니다."`
    * 3명 이상: `"민수님 외 2명이 입력중입니다."` (본인 제외 가나다 순 정렬을 통해 일관된 위치 보장)
  * 응답 데이터 구조에 `typingUserIds` 배열을 함께 전달하여 프론트엔드 UI 처리 편의성 제공.
* **독립 HTML/JS 테스트 스크립트 작성**:
  * 포스트맨 환경의 한계를 극복하기 위해 직접 테스트용 HTML 웹소켓 스크립트를 제작하여 F12 콘솔 기반 사전 검증 완결.

## 3. 클라이언트 맞춤형 API 스펙 리팩토링 및 촘촘한 예외 검증

프론트엔드 연동 편의성과 비즈니스 도메인 규칙 준수를 위한 정밀 리팩토링을 진행했습니다.

#### 3-1. 방명록 목록 조회 (쿼리 스트링전환 및 서버 판단 제어)
* **문제**: URL PathVariable 사용 시 프론트엔드에서 접속 유저의 도시 ID를 파악할 수 없어 "내가 남의 도시에 남긴 방명록" 조회가 불가한 한계 발생.
* **해결**: 슬랙 소통을 통해 쿼리스트링 방식(`?targetUserId=`)으로 전환.
  * 파라미터가 없거나 본인 ID일 경우 ➔ "남이 내 도시에 남긴 방명록"
  * 파라미터가 있고 로그인 유저 ID와 다를 경우 ➔ "내가 해당 도시에 남긴 방명록"으로 서버 단에서 판단 및 반환.
  * 컨트롤러 단에서 미입력 시 로그인 유저 ID를 채우도록 구현하여 서비스 계층 변경을 최소화.

> **[증적 자료 4] 프론트엔드와의 협업 및 스펙 재설계 슬랙 소통**
> 
> ![슬랙 소통 내역](./module5/images/slack_communication.png)

### 3-2. 채팅방 멤버 목록 조회 (신규 추가 및 정렬 규격화)
* **권한 검증**: 해당 채팅방 멤버가 아닐 경우 ➡️ `"해당 채팅방에 접근할 권한이 없습니다."` (403/400 예외 방어)
* **목록 가공 및 정렬**:
  1. 로그인 유저는 결과 목록의 최상단에 고정하며 닉네임 뒤에 `"(나)"` 수식어 부여.
  2. 나머지 멤버는 가나다 순으로 정렬.
  3. 역할(Role) 기반 필드 제어: 강사 역할은 `name` 포함 반환, 학생 역할은 `name`을 `null`로 익명성 제어.

### 3-3. 알림 라이프사이클 UX 연동 강화
* **열품타(그룹 스터디) 초대 알림 확충**:
  * 그룹 스터디 초대 발생 시 `"{초대자 닉네임}님이 그룹 스터디에 초대했습니다."` 알림 생성 및 웹소켓 전송.
  * 앱별 알림 개수 연산 로직에 열품타 초대 알림(`studyCount`) 항목 추가 합산.
* **친구 요청 수락/거절 시 알림 자동 읽음 처리**:
  * 친구 요청 수락 또는 거절 버튼 클릭 시, 사용자 편의성을 위해 해당 요청과 관련된 알림을 백엔드에서 자동으로 읽음(`isRead = true`) 처리하도록 라이프사이클 연동.

## 4. DBA 역할 수행: Flyway 마이그레이션 통제 및 더미 데이터 수선

팀 내 형상 관리 결함과 더미 데이터 오염을 해결하기 위해 DBA 리더십을 발휘했습니다.

* **Flyway 마이그레이션 컨벤션 통제 및 충돌 해결**:
  * 다른 팀원이 도입한 Flyway에서 발생한 파일명 컨벤션 미준수(`__` 누락) 및 스크립트 내부 `USE [DB_NAME]` 구문 삽입 문제 확인.
  * `USE` 구문을 일괄 제거하여 타 로컬 DB 환경 실행 에러를 해결하고 명확한 Flyway 히스토리 관리 체계 정립.
* **대규모 배포 더미 데이터 정합성 수선**:
  * 가입일(`created_at`), 수강 상태(`enrollment`), 진도율(`total_progress`), 완료 여부(`is_completed`) 간 데이터 불일치로 연동 테스트가 차단되던 문제 파악.
  * 300여 건 이상의 더미 데이터 연관관계를 직접 전수 검증 및 수선하여 배포 환경의 통합 테스트 가동 안정성 확보.

### 4-1. 모듈 5 데이터베이스 구조 (ERD)

## 5. 한계 및 향후 개선 과제 (Limitations & Next Steps)

* **JPA 엔티티 간 강결합 문제**:
  * 빠른 기능 개발 과정에서 타 도메인 연관관계 처리를 위해 `JpaEntity`를 직접 참조하는 구조가 일부 잔존함. 향후 완전한 바운디드 컨텍스트(Bounded Context) 분리를 위해 식별자(`Id`) 참조 및 비동기 이벤트 통신 구조로 리팩토링 필요.
* **ENUM 활용을 통한 타입 안전성 확보**:
  * 알림 타입 및 메시지 상태 값 처리를 위해 ENUM 클래스를 정의했으나, 일부 서비스 로직에서 문자열(`String`) 직접 비교 방식이 잔존함. 타입 안전성(Type Safety) 확보를 위한 정밀 코드 리팩토링 필요.
* **Websocket 최소 갱신 시그널 및 N+1 문제**:
  * 유저 급증 시 웹소켓 갱신을 위한 CUD 연산 과정에서 조회 서비스가 추가 호출되는 잔존 N+1 구조를 발견함. 향후 이벤트 기반 메시징 도입을 통한 N+1 조회 부담 개선 필요.
